Controles de segurança aplicados por camada (Diagrama 1):

  • Cloudflare: único ponto de entrada público — só ela conhece o "segredo" X-Origin-Verify da API e é quem tem os CNAMEs oficiais
  • API Gateway/Lambda: rejeita (403) qualquer requisição sem o header X-Origin-Verify correto — bloqueia acesso direto à URL da AWS
  • S3: buckets 100% privados, "Block Public Access" ativo — leitura só é permitida ao CloudFront via Origin Access Control (OAC)
  • DynamoDB: nenhum endpoint público/porta aberta — acesso só via API AWS assinada (SigV4) pela IAM Role do Lambda, restrita a esta tabela
  • Protocolo único de borda: HTTPS/443 (TLS) — HTTP sempre redirecionado; certificados emitidos via AWS ACM (validação DNS)
  • Portas: 443 (HTTPS, único caminho público) · Lambda→DynamoDB e CloudFront→S3 usam a API interna da AWS, sem porta/IP público exposto
  • Regra geral aplicada em todas as camadas: tudo bloqueado por padrão, exceto o estritamente necessário para o funcionamento
  • DNS vs. tráfego: a resolução DNS dos domínios app.* e api.* (A/CNAME) acontece uma vez, no navegador, apontando para a borda da Cloudflare; o tráfego HTTPS que vem depois vai direto a esse edge, que decide para qual origem AWS encaminhar
  • Origem real das chamadas à API: é o JavaScript do SPA React executando no navegador do usuário (funções axios.get/post/patch/delete em App.js) — não existe um serviço de front-end fazendo esse proxy; o front-end é só arquivos estáticos servidos pelo CloudFront

Observabilidade (Diagrama 2) — resumo do que é gerenciado pelo provedor:

  • API Gateway e DynamoDB são serviços gerenciados que já reúnem geração e publicação da métrica — não existe uma etapa de "coleta" separada como no canário (que precisou de uma função nova porque não existe métrica nativa de "o domínio está no ar")
  • Os detalhes internos de como a AWS calcula/agrega essas métricas nativas (ex.: percentis de latência do API Gateway) não são visíveis ao grupo — são administrados pelo provedor; o grupo só consome o resultado publicado no CloudWatch
  • Os logs do TodoFunction e do HealthCheckFunction são a única fonte de dados que o grupo precisou instrumentar (ver Seção de Logs na documentação)
